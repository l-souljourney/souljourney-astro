# EdgeOne Makers 部署规则

修改发布链路、调整 Makers 项目配置或排查部署失败时读取。

## 项目类型互斥

- Makers 项目分两类且**在创建时确定，不可转换**：Git 集成型（`Provider: Github` 等）与直接上传型（`Provider: Upload`）。
- `edgeone makers deploy` 只能部署直接上传型；对 Git 集成型直接报错（"This project type does not support deploy"）。
- 本站目标形态是 **Git 集成型**：GitHub 是唯一源，Makers 侧拉取并构建。不要在同一项目上混用两种形态。

## 环境模型

- 每个项目固定有**生产**与**预览**两个环境，均不可删除，各自独立拥有域名与环境变量。
- 生产环境关联生产分支（`main`）；预览环境关联其余所有分支。
- 自定义域名按环境绑定，始终指向该环境**最近一次成功部署**；该环境的部署若被全部删除，域名返回 404。
- 生产环境尚无成功部署时，项目级默认域名没有内容（返回 404）。这是"域名能解析但站点 404"的常见原因。

## 加速区域与备案

- 加速区域在创建项目时确定，决定节点资源与**是否需要 ICP 备案**。
- 加速区域包含中国大陆时，绑定的自定义域名必须先完成 ICP 备案。
- 本站自定义域名已有备案号，见 `src/config.ts` 的 `ICP`。

## 触发方式

- **Git 自动触发：默认只有主分支的提交会自动触发部署。** 非主分支不自动构建，这是平台默认行为，不是项目配置问题；非主分支要用部署钩子或控制台手动触发。
- **部署钩子**：控制台「项目设置 - 部署钩子」按分支创建，HTTP POST 触发，**无需认证**（URL 本身即凭证，不可泄露，泄露后应立即删除重建）。
- **控制台手动**：项目列表「重新部署」，或对某条部署记录重新部署。

## 构建配置

- 可配置：根目录、输出目录、构建命令、安装命令、Node.js 版本。
- 本站：根目录 `./`、输出目录 `dist`、安装命令 `pnpm install`。平台支持 pnpm，识别 `pnpm-lock.yaml`。
- 构建命令在 Bash shell 中执行，可用 `&&` 串联，因此**发布门禁直接写进构建命令**；门禁失败即构建失败，不会产生新部署，线上保持上一版。

### Node 版本（容易踩坑）

- **`.nvmrc` 优先级高于项目设置**：平台会尝试切到 `.nvmrc` 指定版本；若该版本不在预装列表，构建在"安装依赖"阶段直接失败（日志表现为 `Switching error: Failed to switch to Node.js <版本>`）。
- 预装版本：14.21.3、16.20.2、18.20.4、20.18.0、22.11.0、22.17.1、22.21.1、24.5.0、24.11.0、24.18.0。
- 通过 nvm 下载的非预装版本**不带包管理器**，`pnpm install` 会失败。
- 因此 `.nvmrc` 必须指向预装版本，且满足 `package.json` 的 `engines.node`。
- 构建日志中出现 `Start validating the configuration file` 段落表示构建配置已通过校验。

## 访问与核验边界

- 每次部署有独立访问域名；项目级默认域名对应生产环境。
- **平台默认域名（`*.edgeone.cool`）有访问门禁**：裸请求返回 401，响应头可见 `X-EOP-MSG: eo_time missing`。生产与预览环境都受同一门禁影响，与部署是否成功无关。
- 通过平台接口取得访问签名后，首次请求返回 302 并种下 `eo_token` / `eo_time` cookie，之后即可正常访问。**因此带凭证的自动化核验是可行的**（命令行保持 cookie jar 跟随跳转即可，不需要浏览器）。
- 但这是"带凭证核验"，**不等于匿名公开访问**。面向搜索引擎和真实用户的匿名公开面，必须绑定自定义域名后再验证。
- 判断"域名能解析但站点 404"时，先确认该环境下是否已有成功部署；判断 401 时，先确认是否缺少访问签名。
- 404 行为由构建产物与路由回退规则决定（当前为纯静态 `dist/404.html` 回退）。

## 查询与自动化

- 官方 SDK：`@edgeone/makers-sdk`（npm），提供 `deployments.deploy / wait / list / listAll / get / getLog`。
  - `deployments.wait` 在成功时返回**可访问的签名地址**；`deployments.get` 返回的地址未签名，不能直接访问。
  - `deployments.getLog` 返回构建日志地址。
  - `deployments.deploy` 以 `Preview` 为目标且项目尚无生产部署时会抛 `ValidationError`。
- `edgeone` CLI 内部另有一套未公开的 HTTP API 用于查询项目与部署，**无公开契约、可能变更，不得作为稳定依赖**；需要时从已安装的 CLI 包中读取，不要硬编码地址、账号标识或访问签名。
- `tccli`（腾讯云 CLI）**不覆盖 Makers**，但覆盖 `teo`（EdgeOne 站点加速）、`dnspod`、`cos`、`ssl` 等存量资源，用于盘点与切换。

## 通知

- 控制台「设置 - 通知」支持站内信 / 邮箱 / 短信；「Webhooks」支持自定义 HTTP POST 端点（可配 Bearer 密钥，失败按指数退避重试 3 次）。
- 事件类型：`deployment.created`、`deployment.succeeded`、`deployment.failed`、`domain.added`、`project.created`、`project.settings.updated`、`project.deleted`。
- 用途：弥补"命令行难以查询部署状态"的缺口，把部署结果接入外部核验。

## 变更纪律

- 改 `.nvmrc`、构建命令或输出目录都会改变生产构建结果，按发布门禁验证。
- 不在本仓库任何文档、日志或代码中写入账号标识、访问签名或凭证。
- 本文件描述平台事实与能力边界，不构成生产切换授权；迁移范围以 Issue 为准。
